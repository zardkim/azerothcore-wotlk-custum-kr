# 플레이어용 런처 + 웹사이트 로그인 연동 계획서

## 0. 기존 런처(`C:\WOW_Legends_Repack\launcher`) 분석 결과

Python(Tkinter + PIL) 기반, PyInstaller로 `.exe` 빌드하는 **서버 운영자용 관리 도구**입니다.
claude.ai/design 목업을 그대로 구현한 블리자드 스타일 크롬(파란 타이틀바 + 좌측 스플래시 +
우측 상태 카드 + PLAY 버튼) UI가 이미 완성되어 있고, 로컬/원격(SSH+Docker) 서버를
시작·중지·모니터링하는 게 핵심 기능입니다.

**중요한 발견**: 이 런처는 애초에 "이미 설치된 클라이언트를 실행"만 하지, **클라이언트를
다운로드하는 기능 자체가 없습니다.** 요청하신 "클라이언트 다운로드"는 완전히 새로 만들어야
하는 기능입니다.

### 모듈별 재사용 가능 여부

| 파일 | 역할 | 플레이어용 런처에 재사용 |
|---|---|---|
| `theme.py` | 색상 팔레트/폰트/배경 (WotLK·Classic 테마) | ✅ 그대로 재사용 |
| `widgets.py` | 그라디언트 버튼/상태 점/토글 (Canvas 커스텀) | ✅ 그대로 재사용 |
| `tooltip.py` | 툴팁 공용 모듈 | ✅ 그대로 재사용 |
| `paths.py` | exe/스크립트 실행 무관하게 경로 찾기 | ✅ 그대로 재사용 |
| `soap_client.py` | SOAP `server info` 호출 + 파싱 (접속자/가동시간/지연) | ✅ **그대로 재사용** — 순수 함수, UI 의존성 없음 |
| `remote_process.py` | TCP 포트/SOAP만으로 상태 확인 (SSH 불필요) | ✅ **그대로 재사용** — 플레이어 런처가 정확히 필요로 하는 패턴 |
| `process_manager.py` | 로컬 프로세스 시작/중지 (mysql/auth/world) | ❌ 불필요 — 플레이어는 서버를 못 켜고 꺼야 함 |
| `remote_conf.py` | SSH로 conf 파일 읽기/쓰기 | ❌ 불필요 — 운영자 전용 기능 |
| `config_store.py`, 설정창 전체 | 서버 경로/DB/SSH 등 운영자용 설정 | ❌ 불필요 |
| GM 명령 콘솔, 계정 관리 창, 게임 설정(경험치 등) 창 | 운영자 전용 | ❌ 불필요 |
| **클라이언트 다운로드** | — | 🆕 **새로 만들어야 함** (기존에 없음) |

**결론**: UI 뼈대(테마/위젯/툴팁)와 서버 상태 확인 로직(SOAP/포트 체크)은 거의 그대로 가져다
쓸 수 있어서 실제 작업량이 크게 줄어듭니다. 새로 만들 것은 ①클라이언트 다운로드 ②플레이어용
심플 화면(서버 관리 UI 다 제거) ③웹사이트와의 연동 세 가지입니다.

## 1. 플레이어용 런처 범위 (요청하신 3가지만)

```
┌─────────────────────────────────┐
│  [로고]              WotLK/Classic│
├──────────────┬────────────────────┤
│              │  ● AzerothCore 온라인 │
│  스플래시     │  접속중 112명 · 가동 3일 │
│  아트         │                    │
│              │  [ 다운로드 / PLAY ]  │
└──────────────┴────────────────────┘
```

- **서버 상태**: `soap_client.parse_server_info()` + `remote_process.RemoteServiceProcess`
  그대로 사용. 운영자가 SSH/경로를 입력할 필요 없이, **서버 주소가 코드에 고정**되어 있음
  (플레이어가 설정할 항목이 아니므로).
- **클라이언트 다운로드** (신규): 클라이언트가 로컬에 없으면 버튼이 "다운로드"로 표시 →
  누르면 zip/설치파일을 내려받아 지정 폴더에 풀고 진행률 표시. 이미 있으면 자동으로
  "PLAY" 상태로 전환.
- **PLAY**: 클라이언트가 있으면 실행 (`subprocess.Popen`, 기존 코드와 동일한 방식).

## 2. 웹사이트 로그인과 연동하는 방법

지금 웹사이트(`ac-web`)에는 로그인 성공 시 세션이 생기고 "지금 플레이하기"가 활성화되도록
이미 만들어져 있습니다. 이 버튼을 클릭했을 때 **런처를 실행/연동**시키는 방법은 이렇습니다:

### 커스텀 URL 프로토콜 (권장)

런처를 설치할 때 Windows 레지스트리에 `wowlegends://` 같은 전용 프로토콜을 등록해둡니다
(Discord의 `discord://`, Steam의 `steam://`와 같은 방식). 그러면:

1. 웹사이트의 "지금 플레이하기" 버튼이 `<a href="wowlegends://play?token=...">`로 바뀝니다.
2. 클릭하면 Windows가 "WOW Launcher를 실행하시겠습니까?"를 한 번 물어보고, 런처가 그
   `token`을 받아 실행됩니다.
3. 런처는 그 토큰으로 **계정명**을 알아내서(예: 로그인 API가 짧은 만료 토큰을 하나 더
   내려주고, 런처가 그 토큰으로 서버에 조회) 화면에 "OOO님, 환영합니다"를 띄웁니다.

**보안 원칙**: 비밀번호 자체는 URL/토큰에 절대 담지 않습니다. 토큰은 1회용·단시간
(예: 60초) 만료로 만들고, "이 사람이 방금 웹에서 로그인에 성공했다"는 사실과 계정명만
전달하는 용도로 씁니다.

**설치 안 된 상태 대응**: 런처가 설치되어 있지 않으면 `wowlegends://` 링크는 아무 반응이
없습니다. 웹사이트에서는 클릭 후 2~3초 내 반응이 없으면 "런처가 설치되어 있지 않다면
다운로드하세요" 안내와 함께 런처 설치파일 다운로드 링크를 보여주는 방식(널리 쓰이는
패턴)으로 처리하면 됩니다.

## 3. "게임 내 자동로그인" — 솔직한 난이도 평가

말씀하신 것처럼 로그인 화면에서 아이디/비번을 자동으로 채우거나 곧바로 통과시키는 건,
**WotLK 클라이언트(WoW.exe)가 그런 공식 기능을 전혀 제공하지 않기 때문에** 아래 두 방식 중
하나로 직접 구현해야 합니다:

| 방식 | 설명 | 난이도 |
|---|---|---|
| **UI 자동화** | 런처가 WoW.exe를 실행한 뒤, 로그인 화면이 뜨는 걸 기다렸다가 키보드 입력을 그 창에 직접 전송(`SendInput` 등)해서 아이디/비번 필드를 채우고 Enter | 중간 — 창 뜨는 타이밍/포커스만 잘 잡으면 비교적 안전. 해상도/UI 스케일 바뀌면 필드 좌표가 흔들릴 수 있음 |
| **메모리 패칭** | wow.exe 프로세스 메모리에서 로그인 관련 주소를 찾아 직접 값을 써넣어 로그인 화면 자체를 건너뜀 | 높음 — 클라이언트 빌드(12340) 전용 오프셋을 알아야 하고, 클라이언트가 조금만 바뀌어도 깨짐. 사실상 리버스 엔지니어링 |

**권장**: 1단계는 자동로그인 없이 다운로드+PLAY+상태 표시만 완성하고, 자동로그인은
**UI 자동화 방식**(키 입력 시뮬레이션)으로 2단계에서 별도로 붙이는 걸 권합니다. 메모리
패칭은 리스크 대비 이득이 크지 않습니다(클라이언트 버전 고정이면 한 번 만들고 안정적으로
쓸 수도 있지만, 유지보수 부담이 계속 남습니다).

## 4. 진행 전 확인하실 것

1. **런처 배포 방식**: 웹사이트에서 설치파일을 다운로드하게 할지, 아니면 클라이언트
   패치 파일과 한 zip에 묶어서 같이 배포할지
2. **커스텀 프로토콜 이름**: `wowlegends://` 처럼 원하시는 스킴 이름
3. **클라이언트 다운로드 파일 위치**: 지금 웹사이트 관리자 페이지의 `patchUrl`(클라이언트
   다운로드 링크)을 런처가 그대로 읽어다 쓰면 될지, 아니면 런처 전용 별도 URL이 필요한지
4. **1단계(다운로드+PLAY+상태) 먼저 만들고 자동로그인은 2단계로 미룰지**, 아니면 처음부터
   같이 진행할지

답 주시면 실제 구현 들어가겠습니다.
