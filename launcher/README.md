# WOW Legends Launcher

`mysql`, `authserver`, `worldserver` 를 콘솔 창 없이 백그라운드로 실행/중지/재시작하고,
상태를 확인할 수 있는 WOW Legends 전용 런처입니다. 디자인은
[claude.ai/design 의 "WoW Launcher" 목업](https://claude.ai/design/p/1069b4b8-88fd-4a95-a681-2be04eb97592)을
그대로 옮겼습니다 (블리자드 런처 스타일의 파란 크롬 타이틀바 + 좌측 스플래시 아트 +
우측 서버 상태 패널 + PLAY 버튼).

## 실행 방법

- **`런처 실행.vbs`** 를 더블클릭하세요. (콘솔 창이 전혀 뜨지 않습니다)
- 또는 터미널에서: `pythonw app.py` (콘솔 없이) / `python app.py` (디버그용, 콘솔 표시)

최초 1회, 필요한 라이브러리를 설치해야 합니다:
```bash
pip install -r requirements.txt
```

## exe 로 빌드하기

Python 설치 없이 더블클릭만으로 실행되는 `.exe` 가 필요하면:

```bash
build.bat
```

`dist\WOW Launcher\WOW Launcher.exe` 가 만들어집니다(PyInstaller `--windowed --onedir`).
`onefile`(exe 하나) 대신 `onedir` 을 씁니다 — onefile 은 실행할 때마다 임시 폴더에 풀었다가
종료할 때 지우는 방식이라 **"failed to remove temporary directory"** 오류가 날 수 있습니다
(주로 백신 실시간 검사가 정리 타이밍과 충돌해서 생김). onedir 은 그런 임시 풀기/정리 과정 자체가
없어서 훨씬 안정적입니다. 그 대신 `WOW Launcher.exe` 옆에 `_internal` 폴더(실행에 필요한
내부 파일 — 지우거나 옮기면 안 됨)가 같이 생깁니다. `assets\`(배경/로고/폰트/아이콘)도 그
옆에 복사해줍니다 — 이미지를 바꾸고 싶으면 재빌드 없이 그 폴더의 파일만 바꾸면 됩니다.

**개인 설정은 빌드에 포함하지 않습니다.** `config\config.json`/`config\presets.json` 은 복사하지 않으므로
배포용 exe 는 항상 기본값 상태로 시작하고, 사용자가 설정 창에서 저장을 눌러야 그 옆에 새로
만들어집니다.

코드를 수정한 뒤에는 `build.bat` 을 다시 실행하면 됩니다(PyInstaller 가 없으면 자동 설치).
`assets\icon.ico` 가 exe 아이콘 리소스로 직접 박히고(우클릭 > 속성 > 자세히 에서 제작자
`zardkim` 도 확인 가능 — `version_info.txt`), 실행 시점에도 `WM_SETICON` + `AppUserModelID`
로 한 번 더 확인해서 작업표시줄에 항상 그 아이콘이 뜨도록 했습니다. 도움말 창 하단과 창
제목(작업표시줄 툴팁/Alt+Tab)에 현재 버전이 표시됩니다.

**버전 관리** — `version.py` 의 `__version__` 이 현재 버전(v0.1.0 부터 시작)이고,
`build.bat` 을 실행할 때마다 `bump_version.py` 가 patch 번호를 자동으로 올려서
(`0.1.0` → `0.1.1` → `0.1.2` …) `version.py` 와 `version_info.txt` 를 둘 다 새로
씁니다. 버전 자체가 소스 파일 안에 그대로 박혀서 exe 에 함께 빌드되므로 실행 위치와
무관하게 항상 올바른 버전이 표시됩니다. 코드 수정 없이 빌드만 다시 하고 싶다면
`bump_version.py` 를 직접 실행하지 말고 `build.bat` 을 쓰세요(같이 처리됨).

**WoW 클라이언트 폴더 등 서버 저장소와 다른 위치/드라이브에 이 exe 를 두는 경우**: 경로
자동 감지는 exe 위치에서 위로 몇 단계까지만 뒤지기 때문에, 서버 폴더가 완전히 다른 드라이브에
있으면 자동으로 못 찾습니다 — 이런 배치라면 설정 창에서 MySQL/AuthServer/WorldServer 경로와
클라이언트 실행 파일을 직접 지정해줘야 합니다. 경로가 비어있거나 틀리면 이제 시작 버튼을
눌렀을 때 바로 오류 메시지로 알려줍니다(예전엔 조용히 실패해서 반응이 없는 것처럼 보였음).

이 exe 폴더(`dist\WOW Launcher\`) 전체를 그대로 옮기면 다른 PC에도, 원하는 폴더(예: WoW
클라이언트 폴더)에도 배포할 수 있습니다(단, 그 PC/폴더 구조와 무관하게 설정 창에서 서버
경로만 맞게 지정해주면 됩니다 — 이 exe 는 런처일 뿐, 서버 파일을 담고 있지 않습니다).

### 다른 사람에게 배포할 공개용 빌드 (`build_public.bat`)

이 PC/서버 전용이 아니라 **다른 사람에게 나눠줄 배포판**이 필요하면 `build.bat` 대신:

```bash
build_public.bat
```

`dist\` 가 아니라 별도 폴더 `dist_public\WOW Launcher\` 에 만들어져서 평소 쓰는 개인용
빌드(`dist\`)를 덮어쓰지 않습니다. `build.bat` 과 다른 점:
- **버전을 자동으로 올리지 않습니다** — 지금 `version.py` 에 있는 버전 그대로 씁니다
  (공개 빌드를 만든다고 개인용 빌드의 버전 번호가 같이 소모되지 않도록).
- **`assets\fonts\`(Cinzel 폰트)를 포함하지 않습니다** — 폰트 파일이 없어도
  `theme.py` 가 자동으로 시스템 세리프 폰트(Georgia 등)로 대체하도록 이미 짜여 있어서,
  폰트를 빼도 실행에는 문제가 없습니다. (참고: 실제로 Cinzel 은 SIL Open Font License
  라이선스라 재배포 자체는 허용되지만, 그래도 완전히 빼고 싶다는 요청에 맞춰 이렇게
  만들었습니다 — 다시 포함하고 싶으면 `build_public.bat` 의 폰트 폴더 삭제 줄만
  지우면 됩니다.)
- `config\config.json`/`config\presets.json` 을 절대 포함하지 않는 것(항상 기본값으로 시작)은
  `build.bat` 과 동일합니다.

⚠️ **폰트 말고 이미지도 확인하세요**: `assets\background.jpg` / `left_side.webp` /
`logo.webp` / `alliance-logo.png` / `horde-logo.png` 등은 블리자드 관련 아트워크일
가능성이 높습니다. 개인적으로 소장/사용하는 건 괜찮지만, 불특정 다수에게 배포하는
버전에 그대로 넣어도 되는지는 이미지 출처에 따라 다를 수 있으니 배포 전에 직접
확인해 주세요(이 스크립트는 이미지는 그대로 포함합니다 — 폰트만 뺍니다).

## 기능

0. **서버 상태 카드 (시작/중지/콘솔 바로 조작)** — 메인 화면 헤더에는 "게임 설정"/
   "계정 관리" 버튼, **▶(모두 시작) / ■(모두 중지)** 아이콘 버튼, IP 표시가 있고
   (예전엔 이 자리에
   개별 조작용 "서버 구동" 다이얼로그를 여는 버튼이 있었는데, 그 다이얼로그 안에 있던
   "모두 시작"/"모두 중지" 를 그 자리로 그대로 옮겨서 다이얼로그 자체를 없앴습니다),
   그 아래에는 MySQL/인증 서버/월드 서버가 가로로 나란히 놓인 카드 3개로 표시됩니다.
   각 카드 상단에는 구분이 쉽도록 실제 아이콘 이미지가 나옵니다 — MySQL 은
   `assets/mysql.webp`(가로로 긴 워드마크라 다른 두 아이콘과 세로 높이가 비슷해 보이도록
   폭을 더 크게 잡음), 인증 서버/월드 서버는 **로컬 모드**에서는 각각의 exe 파일에 박혀
   있는 아이콘을 직접 추출해서 보여주고, **원격 모드**에서는(로컬 exe 파일이 있어도 지금
   실행 중인 것과 무관해서 의미가 없으므로) `assets/authserver.ico` / `worldserver.ico`
   번들 아이콘을 대신 보여줍니다 - exe 추출이 실패하는 경우(exe 를 못 찾음)에도 같은
   번들 아이콘으로 대체되어 카드가 아이콘 없이 비어 보이지 않습니다. 서버를 전환하면
   (로컬 ↔ 원격이 바뀌면) 이 아이콘도 바로 다시 계산됩니다. 그 아래에 상태
   점(색) + 이름 + 상태 텍스트, 그리고 그 카드 안에서 바로 **▶(시작) / ■(중지) /
   콘솔 보기(`>_`)** 아이콘 버튼으로 조작할 수 있습니다.
   - **콘솔 보기(`>_`) 버튼 색 구분**: 눌러서 콘솔창을 연 서비스는 그 서비스의 `>_`
     버튼만 초록색으로 바뀌어서, 지금 어떤 서비스의 콘솔이 열려있는지 버튼 색만 보고도
     바로 알 수 있습니다. 다시 누르면(닫으면) 원래 색으로 돌아갑니다.
   - 런처 실행 시 자동 시작이 진행되는 동안에는 "서버 상태" 제목이 잠깐
     "서버 상태 — 자동시작중..." 으로 바뀌었다가, 다 끝나면 원래대로 돌아옵니다
     (모두 시작/모두 중지가 아이콘 버튼이 되면서 글자를 바꿔 보여줄 자리가 따로
     없어져서, 진행 상황은 이 제목으로 대신 알려줍니다).
1. **콘솔 창 숨김** — MySQL / AuthServer / WorldServer 는 콘솔을 실제로는 만들되(완전히 없애버리는
   `CREATE_NO_WINDOW` 대신) 시작할 때 창만 숨겨서 띄웁니다. 그래서 평소엔 도스창이 전혀 보이지
   않지만, 각 상태 카드 우측의 **`>_` 아이콘**을 누르면 그 숨겨둔 콘솔창을 다시 볼 수 있고,
   **한 번 더 누르면 다시 숨겨집니다** (토글). 서버가 실행 중일 때만 활성화됩니다. 창 제목이
   아니라 프로세스(pid)에 직접 붙어서 찾기 때문에 서버가 스스로 콘솔 제목을 바꿔도 항상
   찾습니다. 설정의 "서버 콘솔 창 표시"를 켜면 처음부터 보이게 시작합니다.
2. **상태 확인** — 1.5초마다 프로세스 실행 여부 + 포트(3306 / 3724 / 8085) 응답 여부를 확인합니다.
   각 상태 카드가 상태 점(초록=실행 중 / 노랑=진행 중 / 빨강=정지됨)과 텍스트로 실시간으로
   보여줍니다. 런처를 껐다 켜도 이미 떠 있는 서버를 다시 인식하며, Windows 의 PID 재사용으로
   인한 오탐을 막기 위해 pid 뿐 아니라 실행파일 경로까지 재확인합니다.
3. **시작 / 중지 / 재시작** — 각 상태 카드의 **▶(시작) / ■(중지)** 아이콘으로, 그리고 메인
   화면 헤더의 **▶(모두 시작) / ■(모두 중지)** 아이콘으로 조작합니다.
   "모두 시작"은 MySQL → (포트 응답 확인) → AuthServer → (포트 응답 확인) → WorldServer 순으로,
   앞 단계가 실제로 응답하는 걸 확인해야 다음 단계를 시작합니다(각 20초까지 대기, 그 안에 못
   올라오면 뒷 단계는 시작하지 않음).
   중지는 3단계로 시도합니다: ① 정상 종료 방법이 있으면(MySQL 의 `mysqladmin shutdown`) 먼저
   시도 → ② 콘솔 창에 닫기 요청(창의 X 를 누른 것과 동일 효과) → ③ 그래도 살아있으면 강제 종료
   (이때 콘솔 창을 실제로 들고 있는 프로세스(conhost.exe 등)도 같이 정리해서 빈 창이 고아로
   남지 않게 함). 예전엔 정상 종료를 시도하지도 않으면서 최대 10초를 그냥 흘려보내는 버그가
   있었는데 고쳤습니다.
   - MySQL 실행파일로 `.exe` 대신 `.bat`(예: `MySQL.bat`) 를 지정해도 됩니다. `.bat` 는
     `cmd.exe /c` 로 감싸서 실행하고, 실제 떠 있는지는 그 배치파일 이름이 명령줄에 들어있는
     `cmd.exe` 를 찾아서 확인합니다 — 실행파일 경로만 보고 판단하면 절대 못 찾기 때문입니다.
     mysqladmin/my.ini 위치는 `.bat` 를 쓰든 `.exe` 를 쓰든 항상 루트 폴더 기준
     `mysql\bin\mysqladmin.exe` / `mysql\my.ini` 로 고정해서 찾습니다.
   - 실행 파일 경로가 잘못됐거나 시작 자체가 실패하면 오류 메시지로 알려줍니다(예전엔
     조용히 실패해서 버튼을 눌러도 반응이 없는 것처럼 보였음).
   - 인증서버/월드서버는 MySQL 없이는 시작 직후 곧바로 종료됩니다(AzerothCore 자체 동작).
     시작/중지 자체는 항상 팝업 없이 조용히 진행되고, 상태 점(빨강/노랑/초록)만으로 결과를
     보여줍니다 — 팝업이 커스텀 창 뒤에 숨어 응답을 기다리며 앱이 멈춘 것처럼 보이는 문제가
     있어서 없앴습니다. 서비스가 시작 직후 곧바로 꺼지면(대개 MySQL 미기동) 원인 파악용으로
     `Auth.log`/`Server.log` 마지막 부분을 `launcher\last_crash.log` 에 조용히 기록합니다.
4. **경로 설정** — 우측 상단 톱니 아이콘(⚙) 에서 MySQL/AuthServer/WorldServer 실행파일 경로,
   DB 접속 정보, 클라이언트 실행 파일, 렐름리스트를 지정할 수 있습니다. exe 옆의 `config\config.json`
   에 저장되며,
   창은 폭 1180px, **좌측 서버 목록 + 우측 설정 항목** 구성입니다. 좌측 사이드바에
   등록된 서버들이 나열되고, 각 행의 **on/off 토글**로 지금 편집할 서버를 고릅니다
   (정확히 하나만 켜져 있을 수 있고, 이미 켜진 서버를 끄려고 하면 바로 다시 켜짐 —
   다른 서버의 토글을 켜야 그쪽으로 전환됩니다. 전환하면 창이 그 서버 기준으로 다시
   열리고, 저장하지 않은 변경사항은 사라집니다). 각 행에 **✎(수정)/✕(삭제)** 아이콘이,
   목록 위에는 **+(추가)** 아이콘이 바로 붙어있어서 별도 창을 열지 않고 목록 자체를
   여기서 바로 관리합니다(✎ 를 누르면 이름/환경을 바꾸는 작은 창이 뜹니다). 우측은
   **가로 3열** 구성입니다 — 위쪽에 **로컬 모드/원격 모드 라디오 버튼**으로 지금
   서버의 방식을 고르고, 그 아래 1열(모드별 정보: 데이터베이스+서버 경로, 또는 SSH
   접속 정보+원격 conf 경로) · 2열(클라이언트 실행 파일+렐름리스트+GM 계정) · 3열
   (화면+실행 옵션). 경로 찾아보기 창에서 `.exe` 뿐 아니라 `.bat` 파일도 선택할 수
   있습니다.
   - **DB 접속 정보 자동 채움**: "인증 서버" 또는 "월드 서버" 경로를 찾아보기(...)로
     지정하면, 그 exe 근처에서 `authserver.conf` 를 자동으로 찾아(같은 폴더 → `configs\`
     → `etc\` → `conf\` 순서로 찾음 — 서버팩마다 conf 위치가 다를 수 있어서) 그 안의
     `LoginDatabaseInfo`("호스트;포트;계정;비밀번호;DB명" 형식) 값을 읽어 MySQL
     호스트/포트/사용자/비밀번호를 자동으로 채워줍니다. 두 경로 중 아무거나 지정해도
     항상 `authserver.conf` 기준으로 채웁니다(같은 서버팩이면 보통 같은 DB 를 씀).
     conf 파일을 못 찾거나 값이 없으면 조용히 아무것도 안 바꾸고 넘어갑니다(팝업 없음).
     `conf_reader.py` 는 `worldserver.conf` 도 같은 방식으로 읽을 수 있고
     (`LoginDatabaseInfo`/`WorldDatabaseInfo`/`CharacterDatabaseInfo` 세 가지 모두),
     아래 11번 "게임 설정" 기능에서 값을 다시 쓰는 데에도 이 모듈을 그대로 씁니다.
   - 메인 화면의 **"게임 설정"** 버튼(서버 상태 헤더, 계정 관리 왼쪽)은 아래 11번
     항목 참고.
   "기본값으로" 버튼을 누르면 DB 사용자는 `root`, 비밀번호는 빈 값, 서버 경로 3개와 클라이언트
   실행 파일은 빈 값으로 되돌립니다(저장을 눌러야 실제로 반영됨).
   설정을 저장하면 클라이언트 실행 파일이 있는 폴더 아래에서 `realmlist.wtf` 를 찾아
   지금 고른 렐름리스트 주소로 자동 갱신합니다. 설정 창, 도움말 창, 메인 창 모두
   화면 정중앙에 뜹니다.
   - **렐름리스트는 최대 5개까지 등록**해두고 드롭다운에서 골라 바로 전환할 수
     있습니다(기본값 `127.0.0.1` 하나). 드롭다운 옆 **"+"** 버튼으로 주소를
     추가하고(이미 5개면 막힘), **"-"** 버튼으로 지금 고른 주소를 삭제합니다(최소
     1개는 항상 남아있어야 함). 로컬 서버(`127.0.0.1`)와 외부 공개 주소를 오갈 때
     매번 주소를 새로 입력할 필요 없이 등록해둔 것 중에서 고르기만 하면 됩니다.
     드롭다운 선택도 다른 필드처럼 "저장" 을 눌러야 실제로 `realmlist.wtf` 에
     반영됩니다.
   - 예전 버전(주소 하나만 저장하던 시절)의 설정을 그대로 갖고 있었다면, 처음 실행
     할 때 그 주소 하나를 목록의 첫 항목으로 자동 이전합니다(별도 조작 불필요).
   - 창 왼쪽에 **서버 목록 사이드바**가 있어서, 여러 서버(로컬 하나, 원격 하나 등)를
     등록해두고 토글로 오가며 쓸 수 있습니다. 자세한 내용은 아래 15번 "서버 관리"
     항목 참고. (예전엔 "프리셋"이라는 이름으로 폼 값 전체를 저장/불러오기 하는
     기능이 있었는데, 서버 관리 기능으로 흡수되면서 없어졌습니다 — 기존에
     저장해두셨던 프리셋은 처음 실행할 때 자동으로 서버 목록으로 옮겨집니다.)
5. **Play 버튼** — 설정에서 지정한 WoW 클라이언트 실행 파일을 실행합니다.
   세 서버가 모두 "실행 중"이어야 활성화됩니다(목업과 동일). 그 왼쪽(스플래시 이미지와
   PLAY 버튼 사이 빈 공간)에는 GM 명령어 `server info` 로 가져온 **접속 · 최고 접속 ·
   가동 · 지연**을 한 줄로 보여주고, 각 항목 앞에 색깔 있는 작은 점(초록/노랑/파랑 —
   글꼴에 없을 수도 있는 그림 아이콘 대신 항상 그려지는 원을 아이콘으로 씀)을 붙여서
   구분하기 쉽게 했습니다. 오른쪽 끝의 **⟳ 새로고침** 아이콘을 누르면 바로 다시
   조회하고, SOAP 호출 1번짜리라 온라인 계정 목록과 달리 무겁지 않아서 **10분마다
   자동으로도** 새로고침됩니다(월드서버 미실행/GM 계정 미설정이면 각 항목이 "—" 로
   비어 있습니다 — 팝업 없음).
   - "접속" 은 실제 접속 세션이 아니라 **월드에 있는 캐릭터 수(Characters in world)**
     를 씁니다 — 봇이 많은 서버(`mod-playerbots`)는 실제 접속 세션("Connected
     players")이 항상 0이라, 그 값을 쓰면 온라인 계정 목록 화면(같은 값을 세는
     `account onlinelist` 기준)과 인원수가 안 맞아 보이는 문제가 있었습니다. "최고
     접속" 은 반대로 실제 접속 세션 기준 최고 동시 접속자 수라 서로 다른 지표입니다.
   - "지연"(Update time diff) 점 색은 200ms 미만 초록, 500ms 미만 노랑, 그 이상
     빨강으로 자동으로 바뀝니다.
   - 가동 시간은 서버가 주는 영어 원문("1 day(s) 3 hour(s) ...")을 그대로 쓰지 않고,
     가장 큰 단위 2개만 골라 "1일 3시간" 처럼 한글로 짧게 다시 조합해서 보여줍니다.
6. **부가 옵션(설정 > 실행 옵션)**
   - 런처 실행 시 자동 시작 — 켜두면 런처를 열 때 3개 서버를 자동으로 순서대로 올립니다.
     자동 시작이 진행되는 동안에는 "서버 상태" 패널 제목이 **"서버 상태 — 자동시작중..."**
     으로 잠깐 바뀌었다가, 다 올라오면(성공/실패와 무관하게) 다시 "서버 상태" 로 돌아옵니다.
   - 게임 종료 시 서버 중지 — Play로 실행한 WoW 클라이언트 프로세스가 종료되면 서버 3개를 자동으로 내립니다.
7. **계정 관리** — 서버 상태 패널의 **"계정 관리"** 버튼(헤더 맨 왼쪽)을 누르면 계정 생성 /
   비밀번호 변경 / GM 권한 설정 / 전체 저장(`saveall`) 을 콘솔을 열지 않고 실행할 수 있는
   창이 뜹니다. 명령어를 직접 치는 게 아니라 버튼을 누르면 나오는 입력 폼(계정명/비밀번호)에
   값을 채우면 자동으로 명령이 조립됩니다 — 참고: [AzerothCore GM 명령어](https://www.azerothcore.org/wiki/gm-commands).
   - 계정 생성 → `account create <계정명> <비밀번호>`
   - 비밀번호 변경 → `account set password <계정명> <새비번> <새비번>`
   - GM 권한 설정 → `account set gmlevel <계정명> 3 -1` (레벨 3 / 모든 렐름, 고정값)
   - 전체 저장 → `saveall`
   - 창 아래쪽 결과창에 각 명령을 실행할 때마다 서버 응답(또는 오류 메시지)이 이어서 쌓입니다.
     항상 보이는 스크롤바는 없지만(어두운 테마와 안 맞는 윈도우 기본 회색 스크롤바라 없앰),
     마우스 휠로는 그대로 위아래로 스크롤할 수 있습니다.
   - 내부적으로는 worldserver 에 내장된 **SOAP 관리자 인터페이스**(`worldserver.conf` 의
     `SOAP.Enabled = 1`, 기본 포트 7878)로 명령을 하나씩 HTTP 요청으로 보냅니다. 콘솔을 열
     필요가 없어서, 이 런처가 서버들을 콘솔 숨김으로 띄우는 방식과 잘 맞습니다.
   - 사용하려면 설정(⚙) > 클라이언트 섹션 아래 **"GM 계정" / "GM 비밀번호"** 에 인게임 GM
     계정 정보를 먼저 입력해야 합니다(입력 안 하면 안내 메시지만 뜨고 실행되지 않음). 월드서버가
     실행 중이 아니면 역시 바로 안내 메시지만 뜨고 SOAP 요청 자체를 보내지 않습니다.
   - **종료 전 자동 저장**: "월드 서버 중지" 또는 "모두 중지" 를 누르면, 실제로 정지시키기
     직전에 `saveall` 을 자동으로 한 번 먼저 보냅니다(GM 계정이 설정돼 있고 월드서버가 실행
     중일 때만; 실패해도 팝업 없이 조용히 넘어가고 정지 자체는 항상 진행됩니다).
8. **창 닫기(X) 확인** — 서버가 하나라도 실행 중일 때 우측 상단 X 버튼(또는 Alt+F4)을
   누르면 "서버를 저장한 뒤 종료하시겠습니까?" 확인창이 뜹니다. 이 확인창은 윈도우 기본
   흰 배경 messagebox 가 아니라 런처와 같은 어두운 남색 + 그라디언트 버튼 디자인으로
   맞춘 자체 다이얼로그(`ConfirmDialog`)입니다.
   - **예** → 월드서버 저장(`saveall`) 후 월드서버 → 인증서버 → MySQL 순으로 정상 종료하고
     런처를 닫습니다("모두 중지" 버튼과 동일한 순서/방식).
   - **아니오** → 서버는 계속 실행한 채로 런처만 작업표시줄로 최소화됩니다(실수로 닫아서
     서버까지 같이 꺼지는 걸 막기 위함).
   - 실행 중인 서버가 하나도 없으면 물어보지 않고 바로 닫힙니다.
9. **온라인 계정 목록(진영별)** — 왼쪽 스플래시 이미지를 클릭하면 그 자리에 지금 접속
   중인 계정을 얼라이언스/호드로 나눠서 보여줍니다. 패널 우측 상단의 **⟳(새로고침)** /
   **✕(닫기)** 아이콘으로도 조작할 수 있습니다 — 새로고침은 패널을 유지한 채 다시
   조회하고, 닫기(또는 목록이 아닐 때 이미지를 다시 클릭)를 누르면 원래 스플래시
   이미지로 돌아옵니다. 얼라이언스/호드 칸 제목 옆에는 `assets/alliance-logo.png` /
   `assets/horde-logo.png` 진영 로고를 작게 붙여서 구분이 쉽게 했습니다.
   - 내부적으로 `.account onlinelist` (SOAP 이라 앞의 점 없이 `account onlinelist` 로
     보냄) 로 접속 중인 계정/캐릭터 목록을 가져오고, 이 명령은 종족 정보를 안 주기
     때문에 캐릭터마다 `.pinfo <캐릭터명>` 을 한 번씩 더 호출해 종족을 얻어 얼라이언스/
     호드로 매깁니다. 두 명령 모두 실제 서버 응답으로 형식을 확인해서 맞췄습니다.
   - 몇 명까지 표시할지는 설정(⚙) > GM 계정 아래 **"온라인 계정 표시수"** 에서 정할 수
     있습니다(기본값 100). 봇이 많이 접속해 있는 서버(예: `mod-playerbots`)라도 로컬
     SOAP 호출이라 100명 기준으로도 몇 초면 다 불러옵니다 — 불러오는 동안 "불러오는
     중... (진행/전체)" 로 진행 상황을 보여줍니다.
   - 계정 관리와 마찬가지로 GM 계정 미설정/월드서버 미실행 상태면 SOAP 호출 없이
     안내 문구만 표시하고, 접속 중인 계정이 0명이면 "지금 접속 중인 계정이 없습니다"
     라고 명확히 표시합니다(빈 목록인지 오류인지 구분되도록).
   - 캐릭터명 등 한글 텍스트는 서버가 UTF-8 이 아니라 시스템 로케일(CP949) 바이트를
     그대로 보내는 경우가 있어서, `soap_client.py` 가 UTF-8 로 먼저 시도하고 실패하면
     CP949 로 다시 디코딩하도록 처리했습니다(라이브 테스트로 실제 확인한 문제).
10. **툴팁** — 뜻이 바로 안 보이는 아이콘 버튼(⚙/?/▶/■/`>_`/⟳/✕, 타이틀바
    최소화·닫기)과 상태 표시(초록/노랑/빨강 상태 점, 서버 정보의 접속/최고 접속/가동/지연
    항목)에 마우스를 잠깐(약 0.45초) 올리면 설명 풍선이 뜹니다. 설정 창의 찾아보기(`...`)
    버튼과 실행 옵션 토글 스위치에도 붙어 있습니다. 새 위젯 종류를 추가로 만들지 않고,
    `tooltip.py`(신규) 의 `Tooltip`(실제 tkinter 위젯용) / `attach_canvas_item`(캔버스에
    직접 그린 점·텍스트 아이템용) 을 만들어서 `GradientButton`/`StatusDot`/`ToggleSwitch`
    (`widgets.py`)가 `tooltip="..."` 인자 하나만 받으면 자동으로 붙도록 했습니다. 기존에
    그 위젯에 있던 `<Enter>`/`<Leave>` 핸들러(커서 모양 변경 등)를 안 덮어쓰도록
    `add="+"` 로 이벤트를 추가했습니다.
11. **게임 설정(경험치/드랍률/퀘스트 등)** — 메인 화면 "서버 상태" 헤더의
    **"게임 설정"** 버튼(계정 관리 왼쪽)을 누르면 `worldserver.conf` 의 게임플레이
    수치 15개를 직접 조정할 수 있는 창이 뜹니다. 이 창은 설정의 `config.json` 이
    아니라 실제 서버가 구동에 쓰는 `worldserver.conf` 파일 자체를 열 때마다 다시
    읽고, 저장 시 그 파일에 바로 다시 씁니다.
    - **탭 구성**: 비행(`AllFlightPaths`/`InstantFlightPaths`) / 시작옵션
      (`StartPlayerMoney`, 옆에 "≈ N 골드" 환산 안내 표시) / 경험치(`Rate.XP.*` 5종) /
      드랍률(`Rate.Drop.*` 9종) / 퀘스트(느낌표 숨김 레벨차 2종·공격대 중 퀘스트 완료
      허용·보상 골드 배율 2종) 5개 탭으로 나눠져 있고, 탭을 눌러도 다른 탭에 입력해둔
      값은 그대로 유지됩니다(탭마다 내용을 다시 그리는 게 아니라 미리 다 만들어두고
      보이기/숨기기만 함 — 안 그러면 "저장"이 지금 탭이 아닌 값을 읽으려 할 때 이미
      지워진 위젯을 참조하게 됨). 항목을 2열로 배치하고 입력칸도 값 자릿수에 맞춰
      좁게 잡아서(배율/레벨차는 4자리, 소지금만 넉넉하게) 드랍률처럼 항목이 9개나
      되는 탭도 스크롤 없이 창 안에 다 들어갑니다.
    - **항목마다 설명과 기본값**: 각 항목 라벨 아래에 무슨 뜻인지 한 줄 설명이 있고,
      라벨 오른쪽의 **"기본값"** 버튼을 누르면 AzerothCore 기본값으로 그 항목만
      되돌립니다(다른 항목엔 영향 없음, "저장"을 눌러야 실제로 파일에 반영됨).
    - 위치는 `conf_reader.py`의 `find_conf_file()`(경로 자동 읽기 기능과 동일한 탐색
      로직)로 "월드 서버" 경로 기준 찾으며, 못 찾으면 안내 문구만 뜨고 아무 필드도
      만들지 않습니다.
    - **줄 단위 부분 수정**: `conf_reader.set_values()`가 파일 전체를 다시 만드는 게
      아니라, 정확히 그 키로 시작하고 바로 공백/`=`으로 이어지는 줄만 찾아 값만
      바꿉니다 (`Rate.XP.Quest` 를 바꿀 때 `Rate.XP.Quest.DF` 줄은 건드리지 않도록 키
      뒤에 다른 문자가 더 이어지면 매치하지 않음). 원래 줄의 정렬 공백과 줄 끝의
      `# 주석`, 그리고 파일의 원래 줄바꿈 방식(LF/CRLF)도 그대로 보존합니다 - 실제
      conf 파일로 검증해보니 원본이 LF 였는데 파이썬 기본 텍스트 쓰기 모드로 그냥
      다시 쓰면 CRLF 로 바뀌어서 건드리지 않은 줄까지 전부 달라진 것처럼 보이는
      문제가 있었고, 그걸 고쳤습니다.
    - **안전장치**: 처음 저장할 때 `worldserver.conf.launcher-bak` 으로 원본을 한 번
      백업해둡니다(그 뒤로는 덮어쓰지 않음). 쓰기는 임시 파일에 다 쓴 뒤 원본 파일
      자리에 원자적으로 교체하는 방식이라, 쓰는 도중 오류가 나도 원본이 깨지지
      않습니다.
    - 값 검증: 배율/구리 값은 숫자가 아니면 저장을 막고 어떤 항목이 잘못됐는지
      알려줍니다.
    - **저장 후 재시작 확인**: 저장이 끝났을 때 월드 서버가 실행 중이면 "지금 저장 후
      재시작하시겠습니까?" 라고 물어보고, 예를 누르면 (기존 "모두 중지"가 하던 것과
      똑같이) `saveall` 로 접속 중인 캐릭터 데이터를 먼저 저장한 뒤 월드 서버를
      재시작합니다(`run_action("worldserver", "restart")` 재사용 — 새 로직을 따로
      만들지 않음). 월드 서버가 애초에 꺼져 있으면 재시작 질문 없이 "다음에 서버를
      시작하면 적용됩니다" 라고만 안내합니다.

14. **로컬/원격 서버 설정** — 서버 하나는 "로컬"(윈도우즈 로컬 프로세스로 직접
    구동) 또는 "원격"(Docker 로 원격지에 올려둔 아제로스코어를 SSH 로 연결)
    둘 중 하나로 동작합니다. 설정 창 위쪽의 **"로컬 모드"/"원격 모드"** 탭을 눌러
    지금 편집 중인 서버의 방식을 고릅니다(게임 설정 창의 탭과 같은 방식). 탭
    콘텐츠(로컬: 데이터베이스/서버 경로, 원격: SSH 접속 정보/원격 conf 경로)만
    바뀌고 렐름리스트·클라이언트·GM 계정·화면·실행 옵션은 두 탭에서 항상 그대로
    보이므로, 모드를 바꿔도 창 크기가 거의 안 변합니다.
    - **원격 1차 범위**: 상태 확인(실행 중인지 표시) · 게임 설정(`worldserver.conf`
      원격 편집) · 계정 관리(SOAP) · 상태 확인 후 Play. **시작/중지/재시작은 지원하지
      않습니다**(원격 서버는 보통 계속 켜져 있다는 전제) — 메인 화면의 ▶/■
      아이콘들은 원격 서버가 활성일 때 회색으로 비활성화됩니다. 클라이언트는 원격
      서버에 직접 접속하므로(런처가 트래픽을 중계하지 않음) "렐름리스트 관리"
      기능으로 원격 서버 주소를 등록해두면 됩니다.
    - **연결 방식**: Windows 10/11 에 기본 내장된 OpenSSH 클라이언트
      (`ssh.exe`/`scp.exe`) 를 그대로 씁니다 - 새 라이브러리를 추가로 묶지 않고,
      이미 쓰고 계신 `~/.ssh/config`/키/known_hosts 를 그대로 활용합니다. 인증은
      **SSH 키 파일만 지원**합니다(비밀번호를 설정 파일에 평문으로 저장하지
      않기 위함). "SSH 개인키 파일" 항목 라벨 옆의 **`?`** 아이콘을 누르면
      `ssh-keygen` 으로 키를 만들고 원격 서버의 `authorized_keys` 에 등록하는
      절차를 명령어(복사 버튼 포함)와 함께 단계별로 안내하는 도움말 창이 뜹니다.
      문제 해결 항목엔 **시놀로지(Synology) NAS 케이스**도 포함돼 있습니다 -
      `~/.ssh`(700)·`authorized_keys`(600) 권한을 다 맞췄는데도 계속 비밀번호를
      물어보면, 시놀로지가 다중 프로토콜(SMB 등) 호환 때문에 **홈 디렉터리 자체를
      기본 777로 만들어두는 경우**가 원인인 경우가 많습니다(`chmod 755 ~` 로 해결,
      ACL이 덮어쓰면 `synoacltool -del ~` 도 같이 실행). sshd는 `authorized_keys` →
      `.ssh` → 홈 디렉터리까지 전부 훑어서 그룹/전체 쓰기 권한이 하나라도 있으면
      키를 조용히 거부하고 비밀번호 인증으로 넘어가기 때문에, 하위 폴더 권한만
      보고는 원인을 못 찾기 쉽습니다.
    - **연결 테스트**: "원격 conf 경로" 아래의 **"연결 테스트"** 버튼을 누르면,
      저장하지 않고 지금 입력된 값 그대로 SSH 접속과 "원격 worldserver.conf 경로"
      파일 읽기를 한 번에 확인합니다. 결과는 색으로 바로 구분됩니다 — **초록 ✅**
      (SSH·conf 읽기 모두 성공), **노랑 ⚠**(SSH는 되는데 conf 파일 읽기만 실패 —
      경로가 틀렸거나 그 파일에 대한 읽기 권한이 없는 경우), **빨강 ❌**(SSH 접속
      자체가 실패). `ssh`가 알려준 실제 오류(호스트를 못 찾음, 연결 거부, 키 인증
      실패 등)를 그대로 보여주고, 백그라운드 스레드에서 실행되어 창이 멈추지
      않습니다.
      - **conf 파일 권한 자동 수정**: SSH 접속은 되는데 conf 파일만 "Permission
        denied"로 못 읽으면, 다른 권한은 건드리지 않고 **읽기 권한만(`chmod o+r`)
        자동으로 한 번 추가**해보고 바로 다시 읽어봅니다. 이걸로 고쳐지면 "권한
        문제를 자동으로 고치고 읽기 성공"이라고 뜨고, 파일 소유자가 SSH 로그인
        계정과 달라서(도커 컨테이너 안쪽 UID로 마운트된 경우 등) `chmod` 자체가
        거부되면 그 이유도 그대로 보여줍니다. 이 자동 수정은 "저장" 버튼이 아니라
        **"연결 테스트" 버튼을 눌렀을 때만** 시도합니다 — 저장은 테마·GM 계정처럼
        원격과 무관한 값을 바꿀 때도 매번 누르게 되는 버튼이라, 거기에 원격 파일
        권한을 건드리는 부수 효과를 붙이면 예상치 못한 타이밍에 서버가 바뀌게
        되기 때문입니다.
      - "원격 worldserver.conf 경로"를 아예 안 채운 채로 테스트하면 이제 노랑
        ⚠으로 "경로가 비어 있습니다"라고 콕 집어 알려줍니다(예전엔 SSH 접속만
        되면 그냥 초록 ✅로 넘어가서, 정작 "게임 설정" 메뉴를 열었을 때에야
        모호한 실패 메시지를 보게 되는 문제가 있었습니다). "게임 설정" 메뉴
        자체도 이 경로가 비어 있을 때와 경로는 있는데 못 가져올 때를 구분해서
        메시지를 보여줍니다.
      - 이 테스트는 `-o BatchMode=yes`(비밀번호 등 어떤 것도 대화형으로 묻지
        않음)로 접속을 시도합니다 - 런처가 백그라운드에서 자동으로 접속해야 하니,
        비밀번호를 입력해줄 사람이 없어서 일부러 이렇게 만들었습니다. 그래서 **직접
        `ssh`로 접속하면 비밀번호를 입력해서 되는데 이 테스트는 실패로 나온다면**,
        SSH 키 인증 자체가 원격 서버에서 아직 받아들여지지 않고 있다는 뜻입니다
        (공개키가 `authorized_keys` 에 제대로 등록되지 않았거나 `~/.ssh` 권한이
        틀린 경우가 대부분) — 테스트 실패 메시지에 "Permission denied" 나
        "publickey" 가 보이면 이 경우로 판단해서 SSH 키 도움말 2번 단계를 다시
        확인하라는 안내를 같이 보여줍니다.
    - **상태 확인은 SSH 가 아니라 순수 네트워크 호출**입니다: MySQL/인증 서버는
      TCP 포트 연결 시도, 월드 서버는 이미 있는 SOAP `server info` 호출 성공
      여부로 판단합니다 — 계정 관리도 같은 이유로 SSH 없이 바로 동작합니다.
      SSH 가 실제로 필요한 건 원격 파일시스템에만 있는 `worldserver.conf` 를
      읽고 쓰는 "게임 설정" 하나뿐입니다.
    - **서버 체크(⟲ 아이콘, 원격 모드 전용)**: 메인 화면 "서버 상태" 제목 줄의
      "게임 설정" 버튼 왼쪽에 있습니다. 원격 모드일 때만 활성화되고, 누르면
      `authserver.conf`의 `RealmServerPort`와 `worldserver.conf`의 `SOAP.Port`를
      SSH로 직접 읽어와서, 설정에 수동으로 입력해둔 인증 서버 포트/SOAP 포트
      값이 실제 conf 파일과 다르면 **자동으로 바로잡고** 그 값으로 바로 접속까지
      확인합니다. 인증 서버 상태는 TCP 포트를 직접 열어보는 방식이라, conf에
      적힌 실제 포트와 설정값이 어긋나 있으면 서버가 켜져 있어도 "정지됨"으로
      잘못 표시되는데, 이 버튼이 그 어긋남을 바로잡아줍니다(수동으로 입력했던
      포트가 실제 값과 다를 수 있는 게 흔한 원인). `worldserver.conf`에
      `SOAP.Enabled = 0`으로 되어 있으면 그것도 따로 경고해줍니다(이러면 SOAP
      자체가 꺼져 있어서 상태 확인·계정 관리가 항상 실패합니다). **`SOAP.IP`가
      `127.0.0.1`(기본값)로 되어 있으면 그것도 콕 집어 경고합니다** — 게임 접속
      포트(WorldServerPort)와 달리 SOAP는 원격 서버(또는 도커 컨테이너) 자기
      자신에게만 열려 있게 되어, 게임 플레이는 정상인데 SOAP 기반 상태 확인·
      계정 관리만 실패하는 흔한 원인입니다. `worldserver.conf`에서 `SOAP.IP`를
      `0.0.0.0`으로 바꾸고 월드 서버를 재시작해야 해결됩니다. 결과는 각
      서비스별 온라인/오프라인과 실패 이유를 보여주는 창으로 뜨고, 상태 카드도
      즉시 갱신됩니다. 매 1.5초 자동 새로고침에서는 SSH를 새로 열지 않고(느려
      지니까) 캐시된 포트만 씁니다 - 그래서 conf가 바뀌면 이 버튼을 한 번씩
      눌러줘야 합니다.
    - **게임 설정 저장 실패 메시지**: 원격 모드에서 "게임 설정"을 고쳐서 저장했는데
      실패하면, `scp`/원격 `mv` 명령이 실제로 낸 오류를 그대로 보여줍니다. 연결과
      conf **읽기**는 되는데 **저장**만 실패한다면 SSH 자체 문제가 아니라 그 conf
      파일(또는 폴더)에 SSH 로그인 계정의 **쓰기** 권한이 없다는 뜻입니다(읽기
      권한 `o+r`과 쓰기 권한은 별개입니다). 이 conf 파일엔 DB 비밀번호도 들어있어
      "모든 사용자에게 쓰기 허용"은 권장하지 않고, 대신 파일 소유자를 SSH
      계정으로 `chown` 하거나, SSH 계정을 파일 소유 그룹에 추가한 뒤 그 그룹에
      쓰기 권한을 주는 방법을 안내합니다.
      - **"subsystem request failed" / "scp: Connection closed"**: 최신 Windows
        OpenSSH 클라이언트(9.0 이상)는 `scp` 기본 동작을 SFTP 프로토콜로 바꿨는데,
        시놀로지 등 일부 `sshd`는 `sftp-server` 서브시스템이 아예 설정되어 있지
        않아 이 요청 자체를 거부합니다. 이 에러가 나면 런처가 자동으로 예전
        (exec 기반) `scp` 프로토콜(`-O` 옵션)로 한 번 더 시도합니다 - 별도 조치
        없이 자동으로 넘어갑니다.
    - **다음 단계(이번엔 안 함)**: 원격 시작/중지/재시작(SSH로 `docker compose`
      명령 실행), 원격 콘솔 로그 스트리밍, `authserver.conf` 기반 DB 자동 채움의
      원격판, Docker Engine API(TCP) 방식 지원.
15. **서버 관리(여러 서버 등록/전환)** — 로고 오른쪽 위에 **서버 목록(☰) ·
    설정(⚙) · 도움말(?)** 세 아이콘이 작은 크기로 한 줄에 나란히 있습니다.
    ☰ 를 누르면 등록해둔 서버 목록이 드롭다운으로 바로 뜨고, 하나를 고르면
    그 자리에서 전환됩니다(상태 카드/배지/PLAY 버튼/`realmlist.wtf` 모두
    즉시 갱신 — 별도 창을 열 필요 없음). 드롭다운 맨 아래 **"서버 관리..."** 를
    고르거나, 서버 상태 패널 제목 옆의 **`[서버 이름 · 로컬/원격]`** 배지를
    누르면 추가/삭제까지 되는 전체 서버 목록 창이 뜹니다. 설정 창을 열면
    좌측 사이드바에서도 같은 목록을 바로 보고 추가(+)/수정(✎)/삭제(✕)까지
    할 수 있습니다(위 4번 항목 참고). 로컬 서버 하나, 원격 서버 하나 하는
    식으로 **여러 서버를 등록해두고 필요할 때 골라서 전환**할 수 있습니다.
    - 서버 이름이 길면 배지가 옆의 버튼들과 겹치지 않도록 **말줄임(예: "메인
      서버 -…")으로 잘려서 표시**되고, 배지에 마우스를 올리면 툴팁으로 전체
      이름을 볼 수 있습니다.
    - 서버마다 로컬/원격 여부, DB/경로 또는 SSH 정보, **인증 서버/월드 서버
      포트**, GM 계정, SOAP 포트, 렐름리스트 목록을 **따로** 가집니다(포트가
      서버마다 다를 수 있어서, "서버 체크"로 원격 서버의 실제 포트를 보정해도
      다른 서버에는 영향이 없습니다 — 예전엔 이 두 포트가 실수로 전역 설정
      취급되어, 원격에서 보정한 포트가 로컬로 전환한 뒤에도 안 지워지고 남아
      인증 서버/월드 서버가 계속 "시작 중"에 멈춰 있는 것처럼 보이는 버그가
      있었는데 고쳤습니다). **클라이언트 실행 파일도 서버별로 따로** 가집니다
      — 서버마다 다른 클라이언트(로케일/패치 레벨이 다른 3.3.5a 등)를 쓸 수
      있기 때문입니다. 반면 테마/폰트/자동 시작 같은 실행 옵션은 **런처
      전체에 하나만** 있고 서버를 바꿔도 그대로 유지됩니다.
    - **"전환"** 버튼으로 그 서버를 활성화합니다 — 메인 화면 상태 카드/배지/PLAY
      버튼이 바로 그 서버 기준으로 새로고침되고, **클라이언트의 `realmlist.wtf`도
      그 서버의 렐름리스트 활성 주소로 자동으로 다시 써집니다**(그래야 전환한
      서버로 Play가 실제로 접속됩니다). **"추가"** 는 이름을 입력하면 로컬 모드
      기본값으로 빈 서버를 만들고 바로 활성화합니다(그다음 설정 창에서 정보를
      채우면 됨). **"수정"** 은 서버 이름·**서버팩 이름(부제목)**·로컬/원격
      환경(모드)을 바로 바꿀 수 있는 작은 창을 엽니다 — 서버팩 이름은 "이
      서버가 어떤 서버팩(예: AzerothCore 3.3.5a WOTLK Repack)인지" 같은
      메모용 부제목으로, 서버 이름 밑에 작게 표시됩니다(비워두면 표시 안 함).
      DB/경로나 SSH 접속 정보 같은 상세 항목은 여전히
      그 서버를 활성화한 뒤 설정 창에서 편집합니다(중복 UI를 안 만들기 위함).
      지금 활성 서버를 수정해서 모드가 바뀌면 메인 화면에 바로 반영되고, 다른
      서버를 수정한 경우엔 그 서버 정보만 저장되고 지금 화면은 그대로입니다.
      **"삭제"** 는 확인 후 제거하며, 서버가 1개만 남았으면 지울 수
      없습니다(항상 최소 1개는 유지) — 활성 서버를 지우면 남은 서버로 자동
      전환되면서 `realmlist.wtf`도 같이 갱신됩니다.
    - 예전에 쓰던 **"프리셋"** 기능(폼 값 전체를 이름 붙여 저장/불러오기)이 이
      기능으로 흡수됐습니다 — 처음 실행할 때 그동안 저장해두신 프리셋들이 자동으로
      서버 목록에 추가됩니다("내 설정" 프리셋은 지금 활성 서버와 값이 같으므로
      중복 추가하지 않음).
16. **GM 명령 콘솔** — "월드 서버" 상태 카드의 ▶ ■ `>_` 버튼 옆에 **"GM"**
    버튼이 있습니다. 누르면 명령 입력창 하나짜리 작은 창이 뜨는데, 여기에
    `.` 없이 원하는 GM 명령을 자유롭게 입력하고(예: `server info`,
    `account onlinelist`, `pinfo 캐릭터명`) **"실행"**(또는 Enter)을 누르면
    설정에 저장된 GM 계정으로 SOAP을 통해 그 명령을 월드 서버로 그대로
    보내고, 결과를 아래 로그 영역에 이어서 쌓아 보여줍니다("지우기" 버튼으로
    로그만 비울 수 있음). "계정 관리" 창의 계정 생성/비밀번호 변경/GM 권한
    설정처럼 미리 정해진 폼이 아니라 **아무 GM 명령이나** 실행할 수 있는
    범용 콘솔입니다. 월드 서버가 실행 중이 아니거나 GM 계정/비밀번호가
    설정 안 돼 있으면 그 사실을 로그에 안내만 하고 실행하지 않으며,
    `.server shutdown` 같은 위험한 명령도 별도 확인창 없이 그대로
    실행되므로(다른 프리셋 명령들과 동일하게) 신중하게 사용해야 합니다.
    원격 모드에서도 "계정 관리"와 동일하게 원격 서버의 SOAP 포트로 그대로
    동작합니다.
## 이미지/폰트로 꾸미기

`launcher\assets\` 폴더에 아래 3개 이미지를 넣으면 반영됩니다 (확장자는 `.jpg` / `.jpeg` /
`.png` / `.webp` 중 아무거나 가능):
- `background.*` — 창 전체에 옅게 깔리는 배경
- `logo.*` — 상단 로고
- `left_side.*` — 왼쪽 사이드바 스플래시 아트

Cinzel 폰트는 이미 `assets\fonts\Cinzel.ttf` 에 내려받아 두었습니다(Google Fonts, SIL Open
Font License). `assets\fonts\` 에 다른 `.ttf`/`.otf`/`.ttc` 파일을 더 넣으면 설정 >
화면 > 폰트 드롭다운에 자동으로 나타납니다(위 13번 항목 참고). 자세한 내용은
`assets\이미지_안내.txt` 참고.

## 알아두면 좋은 점

- **상태 확인은 항상 백그라운드에서**: 서버 3개의 실행 상태를 1.5초마다 확인하는데,
  포트가 닫혀있을 때 접속을 시도하면(예: 꺼져있는 서버) 이 PC 환경에서는 즉시 거절되지
  않고 소켓 타임아웃(최대 0.4초)을 그대로 기다리는 경우가 있었습니다. 이 확인을 메인
  스레드에서 그대로 부르면 꺼져있는 서비스가 많을수록(최대 3개 × 0.4초 = 1.2초) 창
  전체가 그만큼 얼어붙어서, 하필 그 타이밍에 설정 창을 열거나 경로 찾아보기 버튼을
  누르면 반응이 늦거나 멈춘 것처럼 느껴지는 원인이었습니다. 지금은 이 확인 자체를
  백그라운드 스레드에서 하고 화면 갱신만 메인 스레드로 넘기도록 고쳐서, 서버가 몇 개
  꺼져있어도 창이 멈추지 않습니다. 처음엔 1.5초 반복 확인(`refresh()`)만 고쳤는데도
  같은 증상이 남아있었던 건, 콘솔 보기 버튼/닫기(X) 버튼/온라인 계정 목록·계정 관리·
  서버 정보 패널이 각자 따로 "지금 월드서버가 실행 중인지" 를 확인할 때도 같은 방식
  (svc.status() 를 그 자리에서 직접 호출)을 쓰고 있어서였습니다 — 이것도 전부
  `refresh()` 가 백그라운드에서 미리 확인해둔 값(`self._last_status`)을 읽도록 고쳐서,
  이제 앱 전체에서 이 종류의 멈춤이 없습니다.
- **정지된 서버는 확인 자체를 쉼**: 백그라운드로 옮긴 뒤에도 꺼져있는 서비스까지 매
  1.5초마다 포트 접속을 계속 시도하는 건 불필요한 낭비라, 어떤 서비스가 "정지됨" 으로
  한 번 확인되면 그 다음부터는(시작 버튼을 누르기 전까지) 그 서비스는 아예 확인하지
  않습니다. "시작" 을 누르면 그 즉시 실제 확인이 다시 시작되고, 시작이 끝난 뒤 실제로
  떠 있는 게 확인되면(RUNNING) 예상치 않은 종료를 놓치지 않도록 계속 확인합니다 — 즉
  "정지 상태 = 확인 안 함", "실행 중/시작 중 = 계속 확인" 입니다.
- **설정 파일 위치**: exe(또는 `app.py`) 바로 옆의 `config\` 폴더 안에 `config.json`/`presets.json`
  으로 저장됩니다. `launcher` 폴더(exe + `_internal` + `assets` + `config`) 하나만 통째로 복사해도
  설정까지 그대로 따라가므로, 런처를 다른 폴더/다른 PC로 옮겨도 독립적으로 그대로 씁니다.
  v0.1.17 이전 버전은 exe 바로 옆에 `config.json`/`presets.json` 을 뒀는데, 그 위치에 파일이
  남아있으면 처음 실행할 때(또는 처음 설정 창을 열 때) 자동으로 `config\` 폴더로 옮겨줘서
  기존 설정을 그대로 이어서 씁니다.
- **경로 기본값 자동 감지**: `config\config.json` 이 없는 첫 실행(또는 개인 설정을 안 담은 배포용 exe)에서는
  MySQL/AuthServer/WorldServer 경로 기본값을 실행 위치부터 위로 몇 단계까지 뒤져서 `authserver.exe`
  가 실제로 있는 폴더를 찾아 채웁니다. 스크립트로 실행하면 `launcher` 의 부모 폴더, exe 로 빌드하면
  exe 가 있는 폴더의 조상 폴더 중에서 찾습니다. **다만 이 런처를 WoW 클라이언트 폴더처럼 서버
  파일과 전혀 다른 위치(다른 드라이브 등)에 두고 실행하면 이 자동 감지는 원리상 못 맞힙니다**
  (관련 없는 두 폴더 트리라 아무리 위로 올라가도 못 찾음) — `root_dir` 값이 엉뚱한 곳으로
  떨어지는데, 그 자체는 문제가 아닙니다(아래 항목 참고). 설정 창에서 MySQL/AuthServer/WorldServer
  경로를 직접 지정해주면 됩니다.
- **각 서버의 실행 폴더(cwd)는 `root_dir` 이 아니라 그 서버에 지정된 실행파일 경로에서 직접
  뽑습니다.** 런처를 서버 파일과 다른 위치(예: WoW 클라이언트 폴더, 다른 드라이브)에 두고
  실행하면 `root_dir` 자동 감지값이 엉뚱한 곳을 가리키게 되는데, 예전엔 AuthServer/WorldServer
  의 실행 폴더를 이 `root_dir` 값으로 그대로 넘겨서 — 실행파일 경로 자체는 정확한데도 —
  AuthServer/WorldServer 가 자기 `configs\authserver.conf` / `configs\worldserver.conf` 를
  엉뚱한 폴더에서 찾다가 못 찾고 시작 직후 조용히 종료해버리는 버그가 있었습니다(MySQL 은
  실행파일 자체 경로에서 실행 폴더를 뽑고 있어서 원래도 이 문제가 없었음). 실제로 클라이언트
  폴더에 복사해서 실행하는 시나리오로 재현·수정을 확인했습니다.
- **인증서버/월드서버는 MySQL이 먼저 떠 있어야 합니다**: 둘 다 시작하자마자 DB 접속을 시도하고,
  실패하면 몇 초 안에 스스로 종료합니다(AzerothCore 자체 동작이지 런처 버그가 아닙니다).
  "모두 시작" 은 MySQL → 인증서버 → 월드서버 순으로, 앞 단계 응답을 최대한 기다렸다가(MySQL
  최대 45초, 인증서버 최대 30초 — 느린 PC 에서 MySQL 초기 구동이 오래 걸릴 수 있어 넉넉하게
  잡음) 다음 단계로 넘어갑니다. "모두 중지" 는 반대 순서(월드서버 → 인증서버 → MySQL)로
  중지합니다.
  **시작/중지는 항상 팝업 없이 조용히 진행되고, 결과는 상태 점(빨강/노랑/초록)으로만
  보여줍니다.** 이전엔 여기서 확인 창/경고 창이 여러 번 떴는데, 전부 실제로 문제였습니다:
  ① MySQL 미기동 확인 창, ② "예상치 않은 종료" 경고 — 둘 다 커스텀 테두리 없는 메인 창
  뒤에 숨어서 응답을 기다리며 앱 전체가 멈춘 것처럼 보이는 문제가 있었고, ② 는 그것과
  별개로 **사용자가 직접 누른 정상적인 중지까지 "예상치 않은 종료"로 오인해서 뜨는 버그**도
  있었습니다(중지가 상태 확인 주기(1.5초)보다 빨리 끝나버리면 "방금 중지 눌렀음" 표시를
  남길 타이밍을 놓침). 지금은 둘 다 팝업으로 안 뜨고, "예상치 않은 종료" 는
  `launcher\last_crash.log` 에 조용히 기록만 됩니다.
- 창이 목업처럼 커스텀 파란 타이틀바(직접 그린 것)를 쓰기 때문에 일반 윈도우 창틀이 없습니다.
